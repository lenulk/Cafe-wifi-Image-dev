# คู่มือติดตั้ง Cafe-WiFi จาก Image สำเร็จรูป

> **สถานะ: เอกสารออกแบบ (เป้าหมาย)** — ยังไม่ได้สร้าง image จริง
> แผนการสร้างอยู่ใน [`image-build-plan.md`](image-build-plan.md)
> ระหว่างนี้ยังติดตั้งด้วย `install.sh` ตามเดิม

เอกสารนี้อธิบายการติดตั้งระบบลง Raspberry Pi 4B ด้วยไฟล์ `cafe-wifi.img.xz`
ที่ติดตั้งซอฟต์แวร์ทุกอย่างไว้แล้ว **ช่างไม่ต้องพิมพ์คำสั่ง CLI เลย** และไม่ต้องรู้ล่วงหน้าว่าร้านใช้วง IP อะไร

ทุกขั้นแยกให้เห็นว่า 👤 **ช่างทำอะไร** และ 🤖 **Pi ทำอะไรเองเบื้องหลัง**

---

## ภาพรวม

```
ที่บ้าน   [0 เตรียมของ] → [1 Flash ~5']
ที่ร้าน   [2 สำรวจเราเตอร์ ~10'] → [3 เสียบ+บูต ~3'] → [4 Wizard ~5']
          → [5 ปิด DHCP/IPv6 ~5'] → [6 ทดสอบ ~5'] → [7 ส่งมอบ]
                                               รวมเวลาหน้างาน ≈ 30 นาที
```

---

## ขั้น 0 — เตรียมของ (ที่บ้าน)

| ของ | หมายเหตุ |
|---|---|
| Raspberry Pi 4B + อะแดปเตอร์ไฟของแท้ (5V 3A) | ไฟไม่พอทำให้การ์ดเสียง่าย |
| SD card ≥ 16 GB (แนะนำ A1/A2) | |
| สาย LAN 1 เส้น | จากช่อง LAN ของเราเตอร์ร้านไปที่ Pi |
| คอมที่ลง Raspberry Pi Imager | Windows / macOS / Linux |
| (ถ้ามี) USB ตั้ง label `CAFEBACKUP` | สำรองข้อมูลนอก SD ดู [`backup-usb.md`](backup-usb.md) |

## ขั้น 1 — Flash การ์ด (ที่บ้าน ~5 นาที)

👤 **ช่าง**
1. เปิด Raspberry Pi Imager → Device: **Raspberry Pi 4** → OS: **Cafe-WiFi OS**
   (Imager ตั้งให้ใช้ repository ของโครงการ จึงมีให้เลือก OS ตัวเดียว)
2. Storage: เลือก SD card **ตรวจชื่อ/ขนาดให้ดี** ห้ามเลือกดิสก์อื่น
3. ตอบ "No" เมื่อ Imager ถามเรื่อง OS customisation (ค่าทั้งหมดตั้งผ่าน wizard แทน)
4. กด Write แล้วรอให้ verify เสร็จ
5. เปิดไดรฟ์ `bootfs` ที่ Windows มองเห็น แล้วรันตัวช่วยเตรียมการ์ด (หรือแก้ `cafewifi.conf` ด้วย Notepad):
   - ชื่อร้าน (แสดงบนหน้า portal)
   - SSH public key ของช่าง (ไม่บังคับ)
6. **จด setup code** ที่ตัวช่วยสร้างให้ (เช่น `K7QM-29XD`) หรือพิมพ์เป็นสติกเกอร์ติดกล่อง Pi

🤖 **เบื้องหลัง**
- Imager ตรวจ SHA-256 ของไฟล์ก่อนเขียน และ verify ซ้ำหลังเขียน
- ตัวช่วยเขียน `cafewifi.conf` ลงส่วน boot (FAT32) ซึ่ง Pi จะอ่านตอนบูตครั้งแรก

> **ใน image ไม่มี** รหัสผ่าน, กุญแจเข้ารหัส, ใบรับรอง หรือ SSH host key ใด ๆ
> ทุกอย่างสร้างใหม่บน Pi แต่ละเครื่องในขั้น 3 (เหตุผลดู [`image-build-plan.md`](image-build-plan.md) §2)

## ขั้น 2 — สำรวจเราเตอร์ร้าน (ที่ร้าน ~10 นาที, **ยังไม่แก้อะไร**)

👤 **ช่าง** เข้าหน้าเว็บของเราเตอร์ แล้วเช็กตามขั้นที่ 0 ใน [`isp-router-runbook.md`](isp-router-runbook.md):

| ต้องมี | ถ้าไม่มี |
|---|---|
| **ปิด DHCP ได้** | **หยุดก่อน** — ลูกค้าจะได้ IP จากเราเตอร์แล้วข้าม portal (ทางสำรอง: ลด pool เหลือ 1 IP) |
| **ปิด IPv6 ฝั่ง LAN ได้** | ทราฟฟิก IPv6 จะข้าม portal ทั้งหมด |
| Client Isolation | ใช้ได้แต่ต้องเขียนเป็นข้อจำกัด |

⚠️ **อย่าเพิ่งปิด DHCP ของเราเตอร์** — Pi ต้องใช้ DHCP นี้ขอ IP ชั่วคราวในขั้น 3

## ขั้น 3 — เสียบสายและบูตครั้งแรก (~3 นาที)

👤 **ช่าง**
1. ใส่การ์ดเข้า Pi
2. ต่อสาย LAN จากช่อง LAN ของเราเตอร์ไปที่ Pi
3. เสียบไฟ แล้วรอดูไฟ LED

| ไฟ LED เขียว (ACT) | ความหมาย |
|---|---|
| กะพริบถี่ | กำลังตั้งค่าครั้งแรก — **ห้ามถอดไฟ** |
| กะพริบช้า ๆ (heartbeat) | พร้อมเข้า wizard |
| กะพริบ 3 ครั้งแล้วหยุด ซ้ำไปเรื่อย ๆ | ผิดพลาด — ดูขั้น "แก้ปัญหา" |

🤖 **Pi บูตครั้งแรก (`cafe-wifi-firstboot.service` ทำงานครั้งเดียว)**
1. ขยาย root filesystem ให้เต็มการ์ด
2. สร้าง `machine-id` และ SSH host keys ใหม่
3. **สร้างความลับประจำเครื่อง:** `NATID_DEK`, `NATID_PEPPER`, `SECRET_KEY`, `FAS_KEY`,
   `DB_PASS`, `setup.token`, พอร์ต SSH สำรอง
4. ตั้ง MariaDB: สร้างผู้ใช้ด้วย `DB_PASS` ใหม่ แล้วรัน schema ใน `sql/`
5. อ่าน `cafewifi.conf` → ตั้งชื่อร้าน ใส่ SSH key แล้ว**ลบไฟล์ทิ้ง**
6. ขอ IP ชั่วคราวจาก DHCP ของเราเตอร์ แล้วประกาศชื่อ `cafewifi.local` (mDNS)
7. เข้า **โหมดตั้งค่า (setup mode):** ยังไม่เปิด dnsmasq, openNDS หรือ nftables ฝั่งลูกค้า

ถ้าไฟดับระหว่างขั้นนี้ เสียบไฟใหม่ได้เลย ทุกขั้นทำซ้ำได้โดยไม่สร้างกุญแจทับของเดิม

## ขั้น 4 — Setup wizard (~5 นาที)

👤 **ช่าง** ใช้มือถือต่อ Wi-Fi ร้าน แล้วเปิด **`http://cafewifi.local`**
(ถ้าเปิดไม่ได้ ให้ดู IP ของ Pi ในหน้า DHCP client list ของเราเตอร์ แล้วเปิดด้วย IP แทน)

| หน้า | ช่างทำอะไร | 🤖 Pi ทำอะไร |
|---|---|---|
| ① ยืนยันตัวตน | กรอก setup code | กรอกผิด 5 ครั้งจะล็อก 15 นาที |
| ② สร้างแอดมิน | ตั้งชื่อผู้ใช้และรหัสผ่านแอดมินคนแรก | hash ด้วย argon2id แล้วทำให้ setup code ใช้ไม่ได้อีก |
| ③ เครือข่าย + ร้าน | ตรวจค่าที่เสนอแล้วกดต่อไป (แก้เองได้) · ชื่อร้าน · เก็บ log กี่วัน (≥ 90) | อ่าน gateway/วงจาก DHCP lease เอง เสนอ **IP ที่ Pi ได้อยู่ตอนนี้** เป็น static (ปิด DHCP เราเตอร์แล้วไม่มีใครได้ซ้ำ และเปิด wizard ที่อยู่เดิมต่อได้) · เสนอวงลูกค้า `10.10.0.1/24` (ถ้าชนวงเราเตอร์จะเลือกวงอื่นให้) |
| ④ เราเตอร์ | ทำตามขั้น 5 แล้วกด "ตรวจสอบ" | ปุ่ม "บันทึก" จะขึ้นเมื่อตรวจผ่านเท่านั้น |
| ⑤ บันทึก | กด "บันทึกและเปิดระบบ" | ตรวจเราเตอร์ซ้ำ (ฝั่ง root) → `install.sh --stage site`: static IP, DNS ของเครื่อง, dnsmasq, nftables, openNDS, nginx, ใบรับรอง HTTPS → ปิด wizard ถาวร ลบ setup code · ล้ม = wizard กลับมาพร้อมสาเหตุ |

## ขั้น 5 — ตั้งค่าเราเตอร์ (wizard จะบอกให้ทำตอนนี้)

wizard แสดงหน้า **"ทำ 3 อย่างนี้ที่เราเตอร์ แล้วกดตรวจสอบ"**

1. ☐ **ปิด DHCP** ของเราเตอร์
2. ☐ **ปิด IPv6** ฝั่ง LAN
3. ☐ เปิด Client Isolation (ถ้ามี)

👤 **ช่าง** ไปแก้ที่เราเตอร์ แล้วกลับมากด **"ตรวจสอบ"**

🤖 **Pi ตรวจให้**

| ตรวจ | วิธี | ไม่ผ่าน |
|---|---|---|
| DHCP ของเราเตอร์ปิดแล้ว | ส่ง DHCPDISCOVER ทดสอบ แล้วดูว่ามีเครื่องอื่นตอบ OFFER ไหม | ❌ "DHCP ของเราเตอร์ยังเปิดอยู่" |
| IPv6 ปิดแล้ว | ฟัง Router Advertisement 10 วินาที | ❌ "IPv6 ยังเปิดอยู่" |

ผ่านครบแล้วปุ่ม "บันทึกและเปิดระบบ" จึงขึ้น (หน้า ⑤) — Pi เปิด dnsmasq, openNDS และ nftables แล้วออกจากโหมดตั้งค่า
(wizard ใช้พอร์ต 80 เดียวกับ nginx จึงหยุดตอบระหว่างบันทึก 1–3 นาที เป็นเรื่องปกติ)

> Pi ยังใช้ IP เดิมได้หลังปิด DHCP ของเราเตอร์ เพราะ lease ยังไม่หมดอายุ (ปกติเป็นชั่วโมงถึงวัน)
> บันทึกเสร็จแล้ว IP นี้กลายเป็น static

> ต้องปิด DHCP ของเราเตอร์ก่อน Pi ค่อยเปิดของตัวเอง ถ้าเปิดพร้อมกันจะมี DHCP สองตัวแย่งกันจ่าย IP
> ระบบนี้จะไม่ยอมไปต่อจนกว่าจะตรวจผ่าน

## ขั้น 6 — ทดสอบ (~5 นาที)

🤖 **Self-test อัตโนมัติ** (ย่อมาจาก `tools/lab_fulltest.sh`)
- ✅ service ทำงานครบ: MariaDB, openNDS, portal, admin, nginx, dnsmasq
- ✅ นาฬิกา sync กับ NTP แล้ว (log ตาม ม.26 ต้องมีเวลาถูก)
- ✅ ออกเน็ตได้ และ DNS ใช้ได้
- ✅ ไฟล์ความลับครบ และสิทธิ์ไฟล์ถูกต้อง

👤 **ช่างทดสอบด้วยมือถือ** (wizard บอกทีละขั้น)
1. ลืม Wi-Fi ร้านแล้วต่อใหม่ → หน้า portal ต้องเด้งขึ้นเอง
2. ลงทะเบียนด้วยข้อมูลทดสอบ
3. เปิด `https://admin.cafe.wifi` แล้วอนุมัติคำขอ (เบราว์เซอร์จะเตือนใบรับรอง self-signed → Advanced → Proceed)
4. มือถือต้องเข้าเน็ตได้
5. ลบข้อมูลทดสอบในหน้า Admin

ผ่านครบแล้วกด **"ดาวน์โหลดรายงานติดตั้ง"** เก็บไว้เป็นหลักฐาน

## ขั้น 7 — ส่งมอบร้าน

👤 **ช่าง**
- [ ] เสียบ USB `CAFEBACKUP` แล้วดูหน้าสถานะว่า "สำรองข้อมูลนอกเครื่อง: ✅"
- [ ] **ดาวน์โหลดไฟล์สำรองกุญแจ** — หน้าแอดมิน → เมนู **สำรองกุญแจ** (แอดมินเท่านั้น) → ยืนยันรหัสบัญชี +
      ตั้งรหัสผ่านล็อกไฟล์ (≥ 12 ตัว คนละอันกับรหัสบัญชี) → ได้ไฟล์ `.cwkey` เก็บนอกเครื่อง ≥ 2 ที่
      และจดรหัสผ่านไว้คนละที่กับไฟล์ — ถ้าการ์ดเสียโดยไม่มีไฟล์นี้ จะถอดเลขบัตรที่เก็บไว้ไม่ได้อีก
      (backup ลง USB มีแค่ฐานข้อมูล **ไม่มีกุญแจ**) · หน้าเดียวกันแสดงว่าสำรองล่าสุดเมื่อไหร่
- [ ] ตั้ง Access Control ของเราเตอร์ตาม [`isp-router-runbook.md`](isp-router-runbook.md) (กัน bypass)
- [ ] สอนพนักงาน: อนุมัติลูกค้า · ดูรายชื่อ · ส่งออกหลักฐานเมื่อมีหมายศาล
- [ ] ให้ร้านเปลี่ยนรหัสผ่านแอดมินเป็นของร้านเอง
- [ ] **เครื่องพนักงานทุกเครื่อง ทำครั้งเดียว:** อนุมัติเครื่องนั้นก่อน → เปิด `https://admin.cafe.wifi`
      → กด "ขั้นสูง → ดำเนินการต่อ" ที่หน้าเตือนใบรับรอง — หลังจากนั้นเข้าหน้าแอดมินได้ตลอดแม้เครื่องหมดสิทธิ์แล้ว
      (Chrome Android ที่**ยังไม่ได้อนุมัติ**และไม่เคยยอมรับใบรับรองนี้ จะขึ้น "Connect to Wi-Fi" แบบไม่มีปุ่มข้าม —
      เพราะใบรับรองเป็น self-signed ระหว่างที่ Chrome คิดว่ายังติด captive portal · ติดตั้ง Pi ใหม่ = ใบรับรองใหม่ ต้องทำซ้ำ)

## แก้ปัญหา

| อาการ | สาเหตุที่เป็นไปได้ | ทำอย่างไร |
|---|---|---|
| เปิด `cafewifi.local` ไม่ได้ | มือถือ Android บางรุ่นไม่รองรับ mDNS | ดู IP ของ Pi ในหน้าเราเตอร์แล้วเปิดด้วย IP |
| SD card เสีย ต้องเปลี่ยนการ์ด | การ์ดหมดอายุ / ไฟดับบ่อย | ติดตั้งการ์ดใหม่จาก image ตามปกติ → คืนกุญแจ: `sudo /opt/cafe-wifi/venv/bin/python -m tools.restore_keys <ไฟล์.cwkey>` (คงค่าเครือข่ายของเครื่องใหม่ ตั้งรหัส MariaDB ให้ตรงให้) → คืนค่า DB จาก USB `CAFEBACKUP` → `sudo systemctl restart cafe-admin cafe-fas cafe-logger` |
| ไฟ LED กะพริบแบบผิดพลาด | การ์ดเสีย / ไม่ได้รับ IP | ตรวจสาย LAN และ DHCP ของเราเตอร์ (ต้องยังเปิดอยู่ในขั้นนี้) |
| ลืม setup code | — | ถอดการ์ดไปใส่คอม แล้วรันตัวช่วยเตรียมการ์ดใหม่ |
| ตั้งเครือข่ายผิดแล้วเข้าไม่ได้ | — | วางไฟล์ว่างชื่อ `factory-reset` ลงไดรฟ์ `bootfs` แล้วบูตใหม่ (ข้อมูลลูกค้าและ log ยังอยู่) |
| ตรวจ "DHCP ยังเปิดอยู่" ไม่ผ่านทั้งที่ปิดแล้ว | มีอุปกรณ์อื่นจ่าย DHCP (เช่น AP ที่ตั้งเป็นโหมด router) | ปิด DHCP บนอุปกรณ์นั้น |
